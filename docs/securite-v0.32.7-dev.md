# Passe de durcissement et limites — v0.32.7-dev

## Périmètre et statut

Revue interne ciblée pour la correction de code et de dépôts **de confiance**. Cette passe ne constitue ni un audit indépendant ni une certification. Les anciens documents indiquent que l'étape 3 reste inachevée ; la définition exacte et complète des quatre étapes ne figure pas dans les éléments conservés de cette passe. On ne peut donc pas déclarer les quatre étapes exécutées dans l'ordre ou achevées. Les étapes qui dépendent de l'achèvement de l'étape 3 restent ouvertes.

## Constats et corrections

1. **Copie préalable d'un fichier isolé.** Avant cette version, `stage_submission_path` utilisait `read_bytes` sans limite pour le fichier demandé et des compagnons. Un fichier de 262 145 octets a été effectivement copié avant que le moteur ne le contrôle. Désormais chaque lecture est limitée à 262 145 octets ; l'octet supplémentaire permet au moteur concerné de constater la taille excessive et de refuser le rendu. L'ouverture utilise `O_NOFOLLOW`, contrôle le type par descripteur et refuse les fichiers ayant plusieurs liens physiques ; une erreur de préparation du fichier principal est signalée comme correction incomplète. Les compagnons non lisibles continuent à être ignorés. Les composants parents et modifications concurrentes restent des risques : ceci n'est pas un instantané atomique.
2. **Fichier d'état du direct.** Une reproduction avec un lien symbolique et une cible factice a confirmé que la v0.32.6 suivait le lien et écrasait la cible avant `chmod`. Le direct écrit désormais un fichier temporaire privé dans le même répertoire puis effectue un remplacement atomique ; un test vérifie que la cible factice reste intacte et que le nouveau fichier est en mode 0600. Un processus possédant le même compte peut encore modifier le répertoire ou les fichiers ; les chemins parents ne sont pas entièrement protégés.
3. **Fin du direct après erreur.** Une erreur simulée de préparation s'échappait avant l'événement de fin et laissait la correction active. Le direct émet désormais un résultat incomplet et notifie les abonnés lors d'une erreur ordinaire ; cela ne garantit pas le nettoyage après SIGKILL, une panne ou un blocage noyau.
4. **C++ et entrée standard.** Un wrapper Python utilisait `subprocess.run(..., capture_output=True)` : les sorties pouvaient être accumulées avant la capture bornée du superviseur. L'entrée standard est désormais fournie directement au processus supervisé par un fichier temporaire ; la capture reste bornée. Test de 10 Kio limité à 512 octets, sans production continue ni charge. Le chemin C++ sous Bubblewrap réel n'a pas été testé ici. Les correcteurs C++ et Python restent partiels et leur conformité aux sujets n'est pas démontrée.
5. **Modules du worker Git.** En reproduisant localement le jeu de modules montés par la v0.32.6, l'import du worker échouait sur `moulinette.c_memguard`. Les modules nécessaires aux imports identifiés ont été ajoutés ; le test copie uniquement ces modules dans un paquet isolé et réussit l'import. Ce test ne contacte aucun dépôt, n'exécute pas Bubblewrap et ne démontre pas que toutes les branches du parcours Git fonctionnent. Ce parcours reste à vérifier réellement sur Ubuntu avec un dépôt de confiance.

## Vérifications réalisées

- Six nouveaux tests ciblés : source trop grande, remplacement de fichier par lien final entre inventaire et ouverture, état live sur lien symbolique, erreur live, petite entrée/sortie C++, import du worker Git en paquet isolé : réussis.
- Suite `python3 tools/test_sans_charge.py` : **392 tests exécutés, dont 70 ignorés ; aucun échec** dans l'environnement de développement. Six témoins nommés de boucle, limites ou remplissage étaient exclus ; `tests_real` et le cgroup-selftest ne sont pas lancés. La suite lance malgré tout des compilations ou programmes de confiance et ne signifie pas consommation nulle. Le journal contient des traces HTTP `BrokenPipeError` durant des scénarios négatifs, sans échec unittest.
- Quatre PDF générés ; ouverture, texte, variantes et polices vérifiés. Test navigateur des téléchargements, sans JavaScript compris, ainsi que humour et reset sur données factices : réussis. Test atome : premier essai échoué sur l'assertion de centrage vertical, second essai réussi ; la cause précise du premier échec n'est pas établie. Le test de la v0.32.6 a aussi réussi dans le même environnement.
- Installation dans un environnement Python temporaire, `moulinette --version` et liste C : réussis. Cette installation n'est pas une validation sur l'Ubuntu de l'utilisateur.
- Bubblewrap et Norminette n'étaient pas disponibles dans cet environnement lors de la passe ; 70 tests sont ignorés. Aucun cgroup systemd réel, téléchargement Git réel ni test C++ sous Bubblewrap réel n'a été validé ici.

## Limites et suites nécessaires

Pas de témoin OOM, de remplissage de tmpfs, de saturation CPU ou de production continue lancé dans cette passe. Les limites cgroup mémoire et CPU en charge ne sont pas validées. Reste notamment : tests fonctionnels sur l'Ubuntu utilisateur, contrôle réel du parcours Git de confiance et du C++ sous Bubblewrap, courses de chemins parents et de SQLite, processus du même UID, descendants détachés, arrêt brutal, stockage global, réseau partagé et noyau partagé. Avant toute prétention de résistance à du code hostile : architecture adaptée, protocole et tests dans un environnement jetable approprié, ainsi qu'un audit indépendant ; aucun de ces éléments n'est acquis ici. Ne pas exécuter de code inconnu sur la base de cette passe.
