# Prompt — audit indépendant de Moulinette Lab v0.15

Audite en lecture la version v0.15 de ce dépôt. C'est un prototype expérimental pour code de confiance ; ne le qualifie jamais de sûr pour du code hostile. Ne modifie aucun fichier du projet. N'utilise pas root, ne modifie ni AppArmor ni le noyau, ne télécharge ni n'exécute de code tiers, ne fais ni fork-bomb, ni saturation mémoire/disque, ni tentative d'évasion destructrice. Décris les tests risqués au lieu de les exécuter.

1. Analyse `moulinette/cgroup_launcher.py`, `cgroup_worker.py`, `cgroup_gate.py`, `scope_protocol.py`, `sandbox_runner.py`, `checker.py`, `norm.py`, le catalogue et les tests. Vérifie le double contrôle du scope avant toute exécution du rendu, les contrôles d'appartenance et de limites, l'héritage par les descendants et l'absence de fallback non isolé.
2. Étudie les courses d'accès au canal et au cgroup, les modifications possibles par le même UID, les limites sous différentes hiérarchies et namespaces, le nettoyage après interruption et les conséquences d'une mort brutale du parent. Distingue ce que prouvent les fichiers cgroup de ce qu'ils ne prouvent pas.
3. Vérifie les montages Bubblewrap, l'environnement et les chemins, l'accès au venv de Norminette, les limites des tmpfs et des sorties, la réduction de protection liée à la recompilation `-fno-stack-protector`, et les risques à compiler puis tester un rendu. La présence de Bubblewrap ou d'un marqueur ne suffit pas à conclure à la sûreté.
4. Vérifie que l'objet effectivement analysé par `nm` est celui lié au harnais, dans les chemins normal et recompilé. Évalue les changements de code conditionnel associés aux flags. Pour les sorties de `nm` mal formées, invalides ou atteignant la limite de capture, vérifie que le verdict n'est pas indûment `passed`. Mentionne les limites intrinsèques de l'analyse statique des symboles.
5. Vérifie la classification `passed`, `failed`, `incomplete`, le passage du rapport dans le protocole cgroup, l'exactitude des identifiants d'exercice, les opérations de compilation autorisées et les scénarios de fallback. Identifie les tests simulés et les environnements qui n'ont pas réellement exercé un scope systemd.
6. Évalue si les exemples et tests correspondent au PDF C 00 v8 sans supposer de tests 42 officiels, et indique les conventions qui ajoutent des exigences au sujet.

Si l'utilisateur l'autorise, exécute seulement `python3 -m unittest discover -s tests -v` et la correction des exemples fournis, pour du code de confiance. Indique les versions et le nombre de tests ignorés, et précise si un scope systemd réel a été observé. Fournis pour chaque constat sa gravité, les références fichier/lignes, les hypothèses, une reproduction non dangereuse si possible, une proposition de correction et les tests associés. Distingue clairement faits observés, hypothèses et limites. Classe aussi explicitement les points qui restent non vérifiés.
